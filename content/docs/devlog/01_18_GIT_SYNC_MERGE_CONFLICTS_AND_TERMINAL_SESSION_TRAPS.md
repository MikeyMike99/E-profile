# Chapter 01_18: Git Sync, Merge Conflicts & Terminal Session Traps

Collaborative development across Windows and WSL Linux environments frequently involves multi-branch workflows, automated synchronization, and terminal recording. This chapter documents how automated Git helper scripts broke due to dirty worktrees, remote URL authentication shifts, and rogue session recordings, and how **`helpers.sh`** stabilized the pipeline.

---

[//]: # (SECTION_ID: SIRA-DEV-01_18-SEC-1)
## What Happened
[//]: # (SECTION_ID: SIRA-DOC-01_18-SEC-1)

While creating automated developer tools to record terminal demonstrations (`rec`) and synchronize code across branches, developers experienced severe workflow disruptions:
- **Terminal Cast File Pollution**: Using `asciinema` to record developer sessions generated `.cast` files throughout arbitrary subdirectories. These unignored files polluted `git status` and risked committing sensitive token strings to public repositories.
- **The SSH URL Breakage**: When switching the remote repository from HTTPS personal access tokens (`https://github.com/...`) to SSH URLs (`git@github.com:...`), automated background sync scripts froze indefinitely, blocked waiting for an interactive SSH key passphrase prompt.
- **The Dirty Tree Merge Refusal**: When running automated sync or branch switching commands, Git aborted with `error: Your local changes to the following files would be overwritten by merge`.
- **Double Prompt Traps**: Poorly scoped shell functions prompted developers twice for commit messages, often dropping into detached HEAD states or failing with syntax errors.

---

[//]: # (SECTION_ID: SIRA-DEV-01_18-SEC-2)
## Why It Happened
[//]: # (SECTION_ID: SIRA-DOC-01_18-SEC-2)

The errors stemmed from shell script concurrency and standard Git safety invariants:
- **Git Protects Uncommitted Data**: By default, Git refuses to switch branches or merge upstream commits if unstaged local modifications exist. Shell scripts that execute `git pull` or `git checkout` without checking working tree state trigger hard errors.
- **Headless Non-Interactive Shells**: Background scripts do not have access to an interactive TTY. When an SSH command requires authentication without an active `ssh-agent`, the subprocess hangs forever.
- **Missing Directory Enforcement**: Calling `asciinema rec` without an explicit destination path saves the `.cast` recording in the current working directory (`pwd`), scattering binary logs across feature workspaces.

```
Uncontrolled Workflow:
asciinema rec (in pwd) ---> Dirty Git Tree ---> git pull fails ---> SSH Prompt Hangs in Headless WSL!

Structured Workflow (helpers.sh):
Auto-route recordings to ~/.devcore/recordings/ ---> git stash autocommit ---> ssh-agent check ---> Clean Fast-Forward Merge!
```

[//]: # (SECTION_ID: SIRA-DEV-01_18-SEC-3)
## The "Why Order Matters" Principle
[//]: # (SECTION_ID: SIRA-DOC-01_18-SEC-3)

In automated version control workflows, strict prerequisite validation prevents repository corruption:
1. **Verify SSH Agent Clearance First**: Before attempting any remote network operation (`fetch`, `push`, `pull`), the script must verify that `ssh-add -l` returns valid keys to prevent non-interactive hangs.
2. **Stash or Stage Local Changes Before Switching**: Never issue `git checkout <branch>` while files are modified. Stash or commit local work before navigating branch boundaries.
3. **Fetch Upstream Before Merging**: Always run `git fetch origin` before `git merge`. Merging without fetching simply merges your local copy of the branch, giving a false sense of synchronization.

## Beginner Coder Q&A
[//]: # (SECTION_ID: SIRA-DEV-01_18-SEC-5)

### What is a `.cast` file?
[//]: # (SECTION_ID: SIRA-DOC-01_18-SEC-5)
A `.cast` file is a lightweight JSON recording generated by `asciinema`. It records the exact timing of text and escape codes displayed in your terminal so terminal sessions can be replayed like a video.

[//]: # (SECTION_ID: SIRA-DEV-01_18-SEC-6)
### Why did switching to SSH cause background scripts to freeze?
[//]: # (SECTION_ID: SIRA-DOC-01_18-SEC-6)
HTTPS commands can pass credentials via stored tokens or credential managers. SSH requires an unlocked private key. If your SSH key has a passphrase and `ssh-agent` is not running, SSH halts and waits for a keyboard password that never comes.

[//]: # (SECTION_ID: SIRA-DEV-01_18-SEC-7)
### How does `helpers.sh` avoid the dirty tree merge error?
[//]: # (SECTION_ID: SIRA-DOC-01_18-SEC-7)
`helpers.sh` checks `git status --porcelain`. If modifications exist, it automatically creates a temporary "WIP before sync" commit or stashes the files, pulls upstream changes cleanly, and re-applies your local work.
