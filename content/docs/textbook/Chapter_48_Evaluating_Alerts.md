# Chapter 48: Introduction to Evaluating Swarm Alerts

## 48.1 The Deluge of JSON

As established in Module 10, the Orchestrator SIEM is constantly ingesting a massive stream of SwarmFlow metadata, Sandbox Event logs, and NGPF (Next-Gen Prompt Firewall) alerts. 

However, generating alerts is only half the battle. A critical skill for any Tier 5 Cybersecurity Analyst operating the Siraugga Engine is the ability to evaluate these alerts and decide what to do with them. If an Admin panics every time the SIEM flags a `read_file` tool execution, they will drown in false positives. They must be able to instantly distinguish between a Tier 2 Modder executing a harmless bash script for their game, and a rogue hacker executing a malicious script to break out of the Sandbox.

## 48.2 Sources of Swarm Alerts

In a decentralized Swarm, alerts do not come from a single source. They are generated by multiple layers of the Orchestrator's defense-in-depth architecture:
1.  **Swarm Behavior Analysis (SBA):** Triggering statistical alerts when token generation spikes.
2.  **Next-Gen Prompt Firewalls (NGPF):** Triggering intrusion alerts when a prompt semantic matches a known jailbreak payload.
3.  **Sandbox Event Logs:** Triggering failure audits when an AI hits a permission boundary.

## 48.3 Master Syllabus for Module 11

Module 11 focuses on the workflow of a Cybersecurity Analyst sitting at the SIEM dashboard. It is broken down into two core objectives:

1.  **Sources of Alerts:** Identifying the JSON structure of a Swarm alert and understanding exactly which Orchestrator subsystem triggered it.
2.  **Overview of Alert Evaluation:** Explaining the standard methodology for classifying and triaging these alerts to determine if they represent a true compromise or a benign AI hallucination.
