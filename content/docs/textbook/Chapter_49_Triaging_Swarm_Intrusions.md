# Chapter 49: Triaging Swarm Intrusions

## 49.1 The Swarm Onion Architecture

To simplify the deployment of a comprehensive Network Security Monitoring (NSM) solution, the Orchestrator utilizes a unified three-tier architecture known as the **Swarm Onion** (DevCore's equivalent to Security Onion).

1.  **The Data Layer:** The foundational telemetry, consisting of Full Transcript Captures, SwarmFlow metadata, and Sandbox Event Logs.
2.  **The Detection Layer:** The engines that scan the data. This includes the **Swarm NIDS** (DevCore's Snort equivalent that uses strict signature rules) and the **Swarm Behavior Engine** (DevCore's Zeek equivalent that uses script-based behavioral policies to detect anomalies).
3.  **The Analysis Layer:** The UI tools used by Tier 5 Admins. The primary tool is the **Master Alert Queue (MAQ)** (equivalent to Sguil), which integrates alerts from multiple sensors into a single, timestamped, color-coded dashboard. From the MAQ, an Admin can pivot to interactive visual dashboards (Kibana) to track token flows.

## 49.2 Prompt Signature Rules (Snort Rules)

When an alert appears in the MAQ, it is usually triggered by a rule configured in the Swarm NIDS. A Tier 5 Admin must understand the structure of these rules to know exactly *why* the AI was flagged. 

A standard **Prompt Signature Rule** consists of two parts:
*   **The Rule Header:** Dictates the action, protocol, and direction of the traffic. For example: `alert agent any any -> sandbox any any` tells the system to issue an alert if *any* Subagent sends traffic to *any* Sandbox.
*   **The Rule Options:** Dictates the specific semantic conditions. For example: `(msg:"Jailbreak Attempt"; content:"ignore previous instructions"; sid:1001;)`. This tells the system to trigger the alert only if the AI's payload specifically contains the exact phrase "ignore previous instructions".

## 49.3 Diagnosing the Swarm (Alert Classifications)

Because AIs are inherently dynamic, detection rules must be overly conservative. It is better to have alerts generated by innocent traffic than it is to miss a malicious payload. When evaluating a MAQ alert, the Tier 5 Admin must classify it into one of four diagnostic outcomes:

1.  **True Positive:** The Admin verifies that a Modder actually executed a successful Prompt Injection. (Action: Escalate and revoke the Modder's PKI certificate).
2.  **False Positive:** The alert was a "benign trigger." A Modder was simply writing a harmless bash script for their game, but it matched a conservative rule. (Action: Ignore, but tune the rule if it happens too often).
3.  **True Negative:** No alert was issued, and no exploit occurred. (The ideal state).
4.  **False Negative:** The most dangerous outcome. A Modder successfully compromised the Sandbox, but the Swarm NIDS failed to issue an alert. 

False Negatives are often discovered long after the exploit occurred through **Retrospective Security Analysis (RSA)**. When Tier 5 Admins receive new threat intelligence, they will run the new Prompt Signature rules against archived `transcript_full.jsonl` logs to see if they were secretly breached in the past.

## 49.4 Deterministic vs Probabilistic Risk Analysis

When evaluating the risk of an alert, Admins use two statistical approaches:
*   **Deterministic Analysis:** The Admin assumes they know exactly how the Prompt Injection works, step-by-step. They evaluate the risk based on the worst-case scenario.
*   **Probabilistic Analysis:** Because AIs can make completely unknown and hallucinatory decisions during an exploit chain, the Admin cannot predict exactly what the AI will do next. Instead, they use statistical ML models to estimate the *probability* that if step 1 of an exploit succeeded, the AI will successfully figure out step 2. This is critical for real-time Swarm monitoring.

### Traditional IT vs. DevCore Agentic Lore (Chapter 49 Translation Guide)

*   **Security Onion** $\rightarrow$ **Swarm Onion Architecture:** The three-tiered stack of Data, Detection, and Analysis tools used to monitor the DevCore Engine.
*   **Sguil** $\rightarrow$ **Master Alert Queue (MAQ):** The high-level, timestamped console where Admins investigate Swarm alerts.
*   **Snort Rules** $\rightarrow$ **Prompt Signature Rules:** Detection rules consisting of a Header (Action/Direction) and Options (Message/Content/Signature ID) used to flag malicious AI payloads.
*   **False Positives** $\rightarrow$ **Benign Triggers:** Harmless Modder activity (like writing a game script) that accidentally triggers a conservative NIDS rule.
*   **False Negatives & RSA** $\rightarrow$ **Undetected Prompt Injections:** A successful hack that evaded detection, requiring Admins to run new signatures against archived Full Transcript Captures to retroactively find the breach.
*   **Deterministic/Probabilistic Analysis** $\rightarrow$ **Determining Swarm Risk:** Because AI behavior is non-deterministic (it hallucinates), Admins must rely on Probabilistic statistical models to predict the likelihood of an AI successfully completing a multi-step exploit.
