# Chapter 46: Types of Swarm Security Data

## 46.1 Orchestrator Alert Data (Swarm IDS)

In traditional IT, an Intrusion Detection System (IDS) like Snort generates **Alert Data** when a network packet matches the known signature of an exploit. 

In the DevCore Engine, the Orchestrator runs a highly specialized **Swarm IDS**. Instead of scanning network packets, it scans real-time AI thought vectors and JSON tool payloads. If a Modder types a prompt that matches a known malicious signature—such as the phrase `"ignore previous instructions"` or a tool call requesting `os.system('rm -rf')`—the Swarm IDS instantly triggers an alert. 

These alerts are concise and highly actionable. They contain the ID of the rule that was triggered, the specific malicious content detected, and the exact Subagent that attempted to process it.

## 46.2 Agentic Sessions vs. Tool Transactions

To properly investigate a Swarm alert, Tier 5 Admins must drill down into two distinct layers of telemetry: Session Data and Transaction Data.

**1. Agentic Session Data (The Conversation Lifecycle)**
Session data is the high-level record of a Subagent's lifespan. It does not contain the actual words the AI generated; it only contains the metadata of the conversation. In traditional networking, sessions are tracked using the "5-Tuples" (Source IP, Dest IP, Port, etc.). In DevCore, sessions are tracked using the **Agentic 5-Tuples**:
1.  **Modder ID:** The user who initiated the swarm.
2.  **Parent Agent ID:** The Orchestrator or Agent that spawned this specific Subagent.
3.  **Subagent ID:** The unique Conversation UUID.
4.  **Model Tier:** The LLM architecture used (e.g., `flash`, `pro`).
5.  **Lifespan Metrics:** The start timestamp, end timestamp, and total tokens generated.

**2. Tool Transaction Data**
If the Session Data is the envelope, the **Transaction Data** is the individual letters inside. Transaction data records the exact messages and tool calls exchanged *during* the Subagent's lifespan. For example, if a Subagent executes `read_file` or `run_command`, the exact JSON request sent to the Orchestrator—and the Orchestrator's resulting status code (e.g., `Completed At: 2026-10-03`)—is recorded as a single transaction log.

## 46.3 Full Transcript Captures (Full Packet Captures)

Sometimes, knowing *what* tools were executed isn't enough; the Admin needs to know exactly *why* the AI decided to execute them.

The DevCore equivalent to a traditional Full Packet Capture is the **Full Transcript Capture** (`transcript_full.jsonl`). This contains the complete, un-truncated internal "thinking" chain-of-thought of the AI, the full text of all files read, and every single generated character. Because of the sheer volume of tokens generated by a large Swarm, Full Transcript Captures are massively storage-intensive. They are only utilized when a Tier 5 Admin needs to extract the deepest contextual evidence of an exploit.

## 46.4 Swarm Behavior Analysis (Statistical Data)

AIs are inherently dynamic; they generate novel text and unexpected solutions to problems. Because of this, static IDS rules and ACLs are easily bypassed. To truly monitor the Swarm, the Orchestrator relies on **Statistical Data**.

**Swarm Behavior Analysis (SBA)** uses machine learning to create a statistical baseline of "normal" AI behavior. For example, the SBA calculates the average rate of tool calls a Subagent makes per minute. If a compromised Subagent suddenly executes 5,000 rapid-fire `read_file` commands in a frantic attempt to scrape the server's hard drive, the SBA will flag it as a statistically significant anomaly, alerting the Admin to a potential data exfiltration event.

## Chapter 46 Conclusion and Master Review

Chapter 46 introduces the foundational logs required for security monitoring. Swarm telemetry is built like a pyramid: massive amounts of Statistical and Session Data sit at the bottom, helping Admins pinpoint anomalies. When an anomaly triggers an Alert, the Admin drills down into the specific Tool Transactions. Finally, if maximum context is required, the Admin pulls the heavy, storage-intensive Full Transcript Capture to see the raw AI logic.

### Traditional IT vs. DevCore Agentic Lore (Chapter 46 Translation Guide)

*   **Alert Data (IDS/Snort)** $\rightarrow$ **Orchestrator Alert Data:** Alerts generated when an AI's prompt or tool payload matches a known malicious signature.
*   **Session Data / 5-Tuples** $\rightarrow$ **Agentic Session Data:** High-level metadata defining a Subagent's lifespan, tracked via the Agentic 5-Tuples (Modder ID, Parent ID, Subagent ID, Model Tier, Metrics).
*   **Transaction Data** $\rightarrow$ **Tool Transaction Data:** The specific tool calls (e.g., `read_file`) and JSON messages exchanged during a session.
*   **Full Packet Captures** $\rightarrow$ **Full Transcript Captures:** The massively detailed `transcript_full.jsonl` files containing the AI's un-truncated internal logic and chain-of-thought.
*   **Statistical Analysis (NBAD/NBA)** $\rightarrow$ **Swarm Behavior Analysis (SBA):** Machine-learning baselines used to detect anomalies in Subagent behavior, such as a sudden spike in token generation or tool abuse.
