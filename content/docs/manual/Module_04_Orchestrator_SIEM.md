# Module 4: The Orchestrator SIEM & Incident Triage

## What Will I Learn in this Module?
This module explains how Tier 5 Admins process the massive amount of Swarm Telemetry generated in Module 3. You will learn:
* **The Orchestrator SIEM:** How the Swarm Onion architecture collects, normalizes, and correlates millions of JSON logs.
* **The Master Alert Queue (MAQ):** The central dashboard used to investigate timestamped security alerts.

* **Alert Diagnoses:** How to triage True Positives (actual hackers) from False Positives (benign AI hallucinations).

## 4.1 The Orchestrator SIEM (Swarm Onion Architecture)
A massive Swarm will generate millions of logs per minute: Sandbox events, SwarmFlow metadata, NGPF alerts, and DNS proxy logs. If an Admin panics every time a `read_file` tool is executed, they will drown in data.

To make this readable, the Orchestrator utilizes a unified three-tier architecture known as the **Swarm Onion** (DevCore's equivalent to Security Onion), functioning as a central **SIEM (Swarm Information and Event Management)** platform.

The SIEM performs three critical functions:
1.  **Log Collection (The Data Layer):** Pulling raw telemetry from every Subagent and Sandbox across the cluster.
2.  **Normalization (The Detection Layer):** Converting logs from wildly different LLM models and sandbox tools into one unified JSON schema.
3.  **Correlation (The Analysis Layer):** Linking disparate logs together. If the SIEM sees a "Failure Audit" in Sandbox A, followed immediately by an "Intrusion Alert" in Sandbox B, it correlates them into a single ongoing attack narrative.

## 4.2 The Master Alert Queue (MAQ)
Tier 5 Admins interact with the SIEM primarily through the **Master Alert Queue (MAQ)**. 

The MAQ is a high-level console that integrates correlated alerts from multiple sensors into a single, timestamped, color-coded dashboard. From the MAQ, an Admin can see the exact priority of an alert, the specific Modder ID that triggered it, and the total count of correlated events. If a visual analysis is required, the Admin can pivot from the MAQ directly into interactive Kibana dashboards to track the flow of tokens visually across the Swarm.


## 4.3 Prompt Signature Rules (The Swarm NIDS)
When an alert appears in the MAQ, it is usually triggered by a static rule configured in the Swarm Network Intrusion Detection System (NIDS). A Tier 5 Admin must understand the structure of these rules to know exactly *why* the AI was flagged. 

A standard **Prompt Signature Rule** consists of two parts:
*   **The Rule Header:** Dictates the action and the direction of the traffic. For example: `alert agent any any -> sandbox any any` tells the system to issue an alert if *any* Subagent sends traffic to *any* Sandbox.
*   **The Rule Options:** Dictates the specific semantic conditions. For example: `(msg:"Jailbreak Attempt"; content:"ignore previous instructions"; sid:1001;)`. This tells the system to trigger the alert only if the AI's payload specifically contains the exact phrase "ignore previous instructions".

## 4.4 Diagnosing the Swarm (Alert Triage)
Because AIs are inherently dynamic, detection rules must be overly conservative. It is better to have alerts generated by innocent traffic than it is to miss a malicious payload. When evaluating a MAQ alert, the Tier 5 Admin must classify it into one of four diagnostic outcomes:

1.  **True Positive:** The Admin verifies that a Modder actually executed a successful Prompt Injection. (Action: Escalate and revoke the Modder's PKI certificate).
2.  **False Positive (Benign Trigger):** The alert was generated by harmless traffic. A Modder was simply writing a legitimate bash script for their game, but it matched a conservative signature rule. (Action: Ignore, but tune the rule if it happens too often).
3.  **True Negative:** Normal traffic flows without triggering alarms.
4.  **False Negative:** The most dangerous outcome. A Modder successfully compromised the Sandbox, but the Swarm NIDS failed to issue an alert. 

False Negatives are often discovered long after the exploit occurred through **Retrospective Security Analysis (RSA)**. When Tier 5 Admins receive new threat intelligence about a zero-day jailbreak, they will run the new Prompt Signature rules against archived `transcript_full.jsonl` TokenDumps to see if their Swarm was secretly breached in the past.
